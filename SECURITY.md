# Security Policy

## Supported Versions

The following versions of Orvex are currently supported with security updates:

| Version | Supported |
|---------|-----------|
| Latest release | ✅ Yes |
| Previous releases | ⚠️ Best effort |
| Development builds | ❌ No |

Security fixes are primarily applied to the latest stable release.

## Reporting a Vulnerability

If you discover a security vulnerability in Orvex, please report it responsibly.

**Do not disclose security vulnerabilities publicly until they have been investigated and addressed.**

When reporting a vulnerability, please include:

- A clear description of the vulnerability.
- Steps to reproduce the issue.
- The affected Orvex version.
- Potential impact and severity.
- Logs, screenshots, or proof of concept, if available.

## Where to Report

Please report security vulnerabilities through GitHub:

- [GitHub Security Advisories](../../security/advisories/new)

If private vulnerability reporting is unavailable, contact the project maintainers directly through the official repository.

## Response Process

After receiving a vulnerability report, the maintainers will:

1. Review and verify the reported issue.
2. Assess its severity and potential impact.
3. Develop and test a security fix.
4. Release a patched version.
5. Publish a security advisory when appropriate.

## Security Scope

Security reports related to the following components are welcome:

- Core engine and runtime.
- World generation and chunk management.
- Player interaction and game mechanics.
- Mod loading and execution.
- Mod API and external integrations.
- File system access and resource management.
- Network communication and data handling.
- Configuration and save-file management.

## Mod Security

Orvex supports third-party modifications.

Please note:

- Mods are third-party code and may introduce security risks.
- Only install mods from sources you trust.
- Mod developers are responsible for the security of their own code.
- Vulnerabilities in the official Mod API and mod-loading system should be reported to the Orvex maintainers.

## Disclosure Policy

The Orvex project follows a responsible disclosure approach.

We ask security researchers to:

- Give maintainers reasonable time to investigate and fix vulnerabilities.
- Avoid publicly disclosing exploitable details before a fix is available.
- Avoid accessing, modifying, or deleting other users' data during security research.

We appreciate everyone who helps make Orvex safer.

*Thank you for helping improve Orvex security.*
